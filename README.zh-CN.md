# Simple Badge

[English](README.md) | 简体中文

在 Obsidian 的 Markdown 编辑器中右键，选择 **插入 Badge**，即可预览、创建并按点选顺序批量插入文字 Badge。当前版本：**0.4.0**。

```html
<span class="badge badge-red">重要</span> <span class="badge badge-green">完成</span>
```

插件提供八种主题色和任意自定义 HEX 颜色，尺寸、圆角、边框及 15% 的半透明背景保持固定，无需单独启用 CSS snippet。

插件界面跟随 Obsidian 的语言：中文语言设置使用简体中文，其他语言使用英文。翻译覆盖菜单、弹窗、设置、颜色名称、状态提示和辅助朗读标签。

如需使用英文，在 Obsidian 的 **设置 → 关于 → 语言** 中选择 **English**，然后按提示重新启动。切换语言会保留已经保存的预设文字。

## 选择颜色

插入窗口中新建 Badge，以及设置页中新增、编辑预设，都使用同一个颜色选择器。

- **主题色**：红、橙、黄、绿、青、蓝、紫、粉。色块展示当前主题下的实际颜色，勾选标记表示当前选择；颜色随 Obsidian 主题自动适配。
- **自定义**：点击颜色方块打开原生取色器，或者直接输入 HEX。取色器、输入框和 Badge 预览同步更新；自定义颜色在切换主题时保留指定色值。
- 支持 `#RRGGBB` 和 `#RGB`，兼容大小写及首尾空格，保存时统一为小写六位格式。因此 `#ABC` 和 `#aabbcc` 视为同一种颜色。暂不接受透明度及其他 CSS 颜色表达式。
- HEX 尚未输入完整或无效时，预览保留上一次有效颜色，暂时禁止保存或添加该草稿；离开输入框后显示格式提示。输入过程中不会自动展开简写，便于连续输入六位色值。

主题色保留现有的纯 class HTML 格式。自定义 Badge 将色值保存在 CSS 变量中，复制 span 到其他笔记时颜色信息会一同保留：

```html
<span class="badge badge-custom" style="--simple-badge-color: #e67e22;">重要</span>
```

两种格式的基础外观均由插件样式提供。

## 批量插入

1. 在 Markdown 编辑位置右键，点击 **插入 Badge**。
2. 左侧显示渲染后的预设。点击前面的圆形按钮，按钮显示从 1 开始的选择顺序。
3. 继续选择其他预设；再次点击已选按钮会取消选择并重新编号，重新选中则追加到末尾。
4. 下方的“插入顺序”显示本次选择，也可以点击其中的条目移除。
5. 点击右下角的 **插入选定 Badge**，一次性插入完整的 span，相邻 span 之间使用一个空格。

每次正常打开窗口都默认不选择任何 Badge。取消或按 Esc 关闭窗口不会插入文本。

## 现场创建

在窗口右侧填写文字、选择颜色，预览会立即更新。

- 点击 **加入本次选择**：作为临时 Badge 追加到本次插入顺序。
- 勾选 **同时保存为预设**，再点击 **加入选择并保存预设**：同时保存到左侧预设列表，下次打开仍可使用。
- 保存操作立即生效；之后取消插入窗口不会撤回已经保存的预设。
- 文字不能为空，首尾空白会被去除。文字按纯文本处理，`&`、`<`、`>` 在 HTML 中自动转义。
- 相同文字和相同颜色会复用已有条目，不会在一次选择中重复加入；相同文字但不同颜色可以分别保存。

## 配置预设

打开 Obsidian **设置 → 第三方插件 → 已安装插件 → Simple Badge 右侧的 ⋮ → 设置**。也可以从设置侧栏“第三方插件”分类下直接点击 **Simple Badge**。入口样式可能随 Obsidian 版本变化。

配置页支持新增、编辑、删除、上移和下移，所有条目都显示渲染后的预览。列表顺序只影响展示，实际插入顺序始终由本次点选决定。

Obsidian 1.13.0 及以上版本支持通过设置搜索找到“新增预设”，也可以按预设文字或颜色搜索各个预设；修改后搜索结果会同步更新。Obsidian 1.8.7–1.12.x 使用标准设置页，不提供搜索集成。

首次使用按界面语言提供四个示例预设：中文为信息（蓝）、完成（绿）、备注（紫）、重要（红）；英文为 Information、Done、Note、Important。可以修改或全部删除；主动清空后不会自动恢复默认值。已经保存的预设不会被自动翻译。

预设保存在当前 vault 的 `.obsidian/plugins/simple-badge/data.json`。保存失败时会显示错误并保留输入；后续可以重试。配置格式损坏或来自不支持的版本时，插件会提示检查文件，不会用默认值覆盖原配置。

0.4.0 同时读取版本 1 和版本 2 的预设数据，保留已有 ID、文字、颜色和顺序；下一次成功保存预设时写入版本 2，单纯加载不会改写文件。0.3.x 无法读取版本 2 数据，如需降级，请提前备份 `data.json`。

修改、删除预设不会修改笔记中已有的 span，也不会悄悄改变已经打开的插入窗口中的选择。

## 编辑行为

- 支持桌面端源码模式和实时预览模式的 Markdown 编辑器右键菜单，包括 Canvas 文本卡片。双击卡片进入编辑状态，再在卡片文字区域内右键，选择 **插入 Badge**。卡片外框菜单和画布空白处菜单不提供该操作。
- 使用打开右键菜单时的主光标位置；存在选区时保留原文，在主选区末尾插入。
- 除相邻 span 之间的一个空格外，不额外添加空格、换行或占位文字。
- 插入后光标位于整个批次之后，一次撤销或重做处理整个批次。
- 窗口打开后原文发生变化，或原编辑器已失效时，点击插入会提示 **重新定位**。点击该按钮后，在新的位置右键打开插入窗口即可继续使用保留的选择和草稿。
- 重新定位暂存仅保留在内存中；取消新窗口、停用插件或退出 Obsidian 会结束该次操作。
- 阅读模式显示渲染后的 Badge；编辑模式沿用 Obsidian 原生的行内 HTML 行为。
- 停用插件后笔记中的 HTML 保留。需要独立保留配色时，可将 `styles.css` 开头的 `.badge`、八个主题色规则及 `.badge-custom` 规则复制到 CSS snippet 中启用。

## 开发与测试

需要 Node.js 20.19+、22.13+ 或 24+，以及 pnpm。

```sh
pnpm install
pnpm lint
pnpm build
pnpm test
```

`pnpm dev` 监听源码并重新构建；`pnpm typecheck` 单独检查类型。开发监听不会自动同步或重载 vault 中的插件。

27 项自动化测试覆盖选择顺序与快照、HTML 转义、批量编辑事务、预设管理、并发保存与失败恢复、语言处理、损坏配置拒绝加载及 Canvas 插入目标校验。颜色测试包括 HEX 格式统一与无效输入、八种主题色翻译、混合 HTML 输出、安全 DOM 预览、等价色值去重、版本 1 配置迁移及版本 2 保存失败恢复。`pnpm lint` 使用 Obsidian 官方 ESLint 推荐规则，要求零警告。

已在 Windows Obsidian **1.13.7** 的 Develop vault 中实际验证：带编号的多选、取消后重排、临时与已保存 Badge 混合插入、HTML 转义、整批撤销与重做、设置页增删改排序、插件重新启用后的预设保留和单一右键入口，以及原文变化后保留选择并重新定位插入。示例保留在 vault 的 `Simple Badge 示例.md`。

0.3.0 还在 Obsidian 英文环境中实际检查了右键菜单、插入窗口、选择计数、成功提示、设置页及预设编辑窗口。英文临时 Badge 与已有中文预设混合插入时顺序正确、特殊字符正常转义，一次撤销可恢复原文。切回中文后，插件界面恢复中文。测试结束后，笔记及预设数据文件的哈希值与测试前一致。

0.3.1 已在 Obsidian 1.13.7 中实际验证设置搜索、搜索结果跳转、预设新增、排序、编辑和删除。修改后的预设名称可立即搜索，删除后对应搜索结果消失。清理测试条目后，笔记和预设数据文件的哈希值与测试前一致。

0.3.2 已在 Obsidian 1.13.7 的 Develop vault 中使用 `test-canvas.canvas` 实测：文本卡片编辑区右键可打开插入窗口；两个预设按点选顺序插入，span 之间保留一个空格；卡片正常渲染并保存到 Canvas 文件，一次撤销恢复原来的空卡片。

0.4.0 已在 Obsidian 1.13.7 中实测原生取色（包括取色弹窗尚未关闭时的实时更新）、HEX 分段连续输入、无效输入提示、简写统一、新增及编辑自定义预设，以及重新启用插件后恢复预设。自定义色与主题色混合插入后，在 Markdown 实时预览、阅读视图及 Canvas 卡片中均能渲染；Canvas 还检查了浅色与深色模式。整批撤销后，两个测试文件的哈希值均与测试前一致。

最低支持 Obsidian 1.8.7，与自动语言识别所用的公开 `getLanguage()` 接口一致，颜色选择器没有引入更高版本的 API 要求。调用新版设置接口前通过 `requireApiVersion("1.13.0")` 检查版本，较旧的受支持版本使用传统设置页。这条旧版本路径、第三方主题及移动端没有完成实际界面验证，当前插件仅声明支持桌面端。旧版内置浏览器若不支持 `color-mix()`，会保留基础 Badge 背景。

## 部署与安装

```sh
pnpm build
pnpm run deploy:dev
```

上述命令将 `main.js`、`manifest.json`、`styles.css` 部署到：

```text
D:\Notes\Develop\.obsidian\plugins\simple-badge
```

其他 vault：

```sh
pnpm run deploy "D:/path/to/vault"
```

在 Obsidian 的“设置 → 第三方插件”中启用 **Simple Badge**。更新后关闭再开启该插件。

也可以将 `simple-badge-0.4.0.zip` 中的三个文件解压到目标 vault 的 `.obsidian/plugins/simple-badge/` 后启用。更新时保留已有的 `data.json`。

部署脚本只复制三个插件文件，不改写预设数据、启用列表或其他插件配置。

## 源码结构

- `src/main.ts`：右键入口、编辑位置校验与插件生命周期。
- `src/editor-target.ts`：记录原编辑器和光标，为笔记及嵌入式编辑器校验插入目标。
- `src/i18n.ts`：英文、简体中文文案及语言识别。
- `src/insert-modal.ts`：预设选择、创建和批量插入窗口。
- `src/settings.ts`：官方设置页与预设编辑窗口。
- `src/badge-form.ts`：两类窗口共用的文字、颜色和预览表单。
- `src/color-picker.ts`：共用的主题色块、原生取色器和带校验的 HEX 输入。
- `src/model.ts`：预设类型、配置校验、选择顺序和 HTML 序列化。
- `src/preset-store.ts`：预设操作与串行持久化。
- `src/badge.ts`：安全的 DOM 预览与编辑器批量事务。
- `styles.css`：Badge 固定样式及插件界面布局。
- `tests/core.test.mjs`：核心行为测试。
- `scripts/deploy.mjs`：复制构建产物到指定 vault。
